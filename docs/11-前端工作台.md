# 生产工作台：设计说明与使用方式

## 1. 目标用户与核心任务

工作台主要服务三类现场角色：

| 角色 | 进入页面后最先要回答的问题 | 页面中的对应位置 |
|---|---|---|
| 生产计划员 / 车间主管 | 今天做到哪了？哪张单会拖交期？ | 总装随工单、工单队列、需要你决定 |
| 班组长 / 操作工 | 当前工序要做什么？怎么报工或暂停？ | 工艺路线、当前工序、工序详情抽屉 |
| 质检 / 仓库协同人员 | 哪道工序卡在质检？哪个物料有缺口？ | 质量放行、物料齐套、批次追溯 |

核心任务按照现场决策顺序排列，而不是按照数据库实体排列：

1. **看清当前节拍**：当前工单、当前工序、已报工数量、剩余交期。
2. **识别阻断点**：缺料暂停、待质检、已审核未下达。
3. **执行下一步**：开始、暂停、完工、报工、放行、下达。
4. **必要时追溯**：从成品批次回到物料批次与供应商。

## 2. 设计概念：数字随工单

制造业里，随工单会跟着一批产品穿过各道工序，记录数量、责任人和放行结果。本页面把这一现场物件转成数字界面：

- 首屏不是通用的“大数字 + 渐变卡片”，而是一张正在流动的随工单。
- 工艺路线用真实工序号（10 / 20 / 30）连接，质检点以菱形门禁标记。
- 当前工序是一个信号灯节点，路线只填充到当前节点；完成、进行中、待开始有不同结构状态。
- 右侧“需要你决定”只放会阻断后道的事件，不把所有通知平铺。

页面采用的独特视觉语言来自车间本身：矿物灰绿底板、涂装车间深绿、安全信号橙、工艺蓝图网格。深绿和海报式大标题承载“现场”，橙色只留给当前风险与主操作。

## 3. 字体、色彩与版式

### 字体

- 中文正文与标题：`HarmonyOS Sans SC / Source Han Sans SC / Microsoft YaHei`，优先保证中文的可读性和工业感。
- 数据与编号：`Bahnschrift SemiCondensed`，用于工单号、批次号、时间、数量和进度，形成“仪表读数”与中文正文的清晰分工。
- 数字启用 tabular numerals，便于队列内纵向比较。

### 色彩

| Token | 色值 | 用途 |
|---|---|---|
| `--board` | `#e6eae4` | 车间调度板底色 |
| `--paper` | `#f6f7f1` | 工单与数据纸面 |
| `--ink` | `#17241f` | 正文与决策栏 |
| `--forest` | `#1e4b41` | 当前工单、主操作、工艺路线 |
| `--signal` | `#d64b2b` | 风险、暂停、当前工位 |
| `--caution` | `#bd8a23` | 质检门禁与提醒 |

### 版式

- 左侧固定导航承载工厂层级；主区域以随工单为全宽视觉锚点。
- 指标轨使用连续刻线而不是四个同构圆角卡片。
- 下半区是 2:1 不对称布局：左侧工单队列，右侧决策栏。
- 设备宽度低于 820px 时切换为底部导航，随工单与操作按钮纵向重排。

### 动效

- 页面载入只做一次工艺路线填充，终点落在当前工序。
- 当前工位使用一个缓慢的雷达脉冲，表达“正在发生”而不是装饰。
- 抽屉、对话框和 Toast 由用户操作触发。
- 在 `prefers-reduced-motion: reduce` 下关闭这些动画。

## 4. 页面路由

工作台使用无需服务端回退的 hash 路由，现有 REST 路由保持不变：

| 页面路由 | 内容 | 调用的现有接口 |
|---|---|---|
| `#/today` | 今日生产、随工单、决策栏、批次脉络、**工单状态分布 / 不良代码构成** | 工单分页、工单详情、`GET /production-service/order/stats/status`、`GET /quality-service/inspection/defect-stats`、库存列表 |
| `#/orders` | 工单列表、筛选、新建工单 | `GET /production-service/order/page`、`POST /production-service/order` |
| `#/orders/:id` | 工艺路线、数量、状态历史、工单流转、齐套 / 报工 / 质检分区 | `GET /production-service/order/{id}`、`POST /production-service/order/{id}/transit`、`/{id}/requirements`、`GET /production-service/report/order/{id}`、`GET /quality-service/inspection/order/{id}` |
| `#/tasks` | 工序任务队列、状态操作、**派工**、报工 | `POST /production-service/work-task/{id}/start\|pause\|resume\|complete\|pass-inspection\|reject-inspection`、`POST /work-task/{id}/dispatch`、`GET /report/new-no`、`POST /report`、`GET /system/user/list` |
| `#/materials` | 现有量 / 预留量 / 可用量，以及**库存作业**（安全库存清单、预留与释放、领料退料、库存对账） | `GET /inventory-service/inventory/list`、`/inventory/below-safety`、`/reservation/order/{id}`、`/reservation/reserve`、`/reservation/release/{id}`、`/issue`、`/issue/return`、`/issue/order/{id}`、`POST /inventory/reconcile` |
| `#/basic` | **基础资料（只读）**：产品 / 物料 / BOM / 工艺路线 | `GET /product-service/product/page`、`/material/page`、`/bom/product/{id}`、`/bom/{productId}/tree`、`/route/product/{id}`、`/route/{routeId}/steps` |
| `#/trace` | 反向与正向批次路径 | `GET /quality-service/trace/backward` |
| `#/quality` | 待质检任务与放行、退回 | 工序任务放行 / 退回接口 |

## 5. 运行方式

### 由网关直接托管（推荐）

前端文件位于 `smart-gateway/src/main/resources/static/`，随网关 Jar 一起发布：

```bash
mvn -pl smart-gateway -am package -DskipTests
java -jar smart-gateway/target/smart-gateway-*.jar
```

打开 `http://localhost:9000/`。前端与 REST 接口同源，不需要额外配置 CORS。静态资源已加入网关鉴权白名单，登录接口仍使用原有 `/system/auth/login`。

### 仅预览界面

```bash
python -m http.server 4173 --directory smart-gateway/src/main/resources/static
```

打开 `http://127.0.0.1:4173/`。没有网关时会自动使用本地演示数据；点击右上角账号可输入 `planner / 123456` 尝试连接网关。

## 6. 真实接口与演示数据

- 默认进入**演示数据**模式，所有按钮可操作并在浏览器内存中回放状态变化，适合无数据库时浏览。
- 通过右上角“接口”或账号入口登录成功后进入**真实接口**模式，订单、工序、报工、库存、基础资料与追溯操作都会走现有网关路由。
- 登录失败不会静默伪装成功，会展示接口错误并保留演示数据。
- 前端不存储密码；JWT 存在 `localStorage`，401 时清除并回退到演示模式。

### 6.1 每个可视化区块的数据来源

工作台上没有任何“看起来是数据、其实是编的”图表。逐个区块的取值如下：

| 区块 | 连接网关后 | 演示模式 |
|---|---|---|
| 工单状态分布 | `GET /production-service/order/stats/status` 的**全库计数**，不受列表分页影响 | 用演示数据集的 6 张工单计数，并在卡片上标注“演示数据集共 N 张” |
| 不良代码构成 | `GET /quality-service/inspection/defect-stats`（不良码 × 判定次数 × 不良数量），取 Top 6 | 不展示图形，明确写“演示数据集没有该口径，此处不展示虚构构成” |
| 工单列表 / 工序 / 报告 / 质检 | 分页与详情接口 | 演示数据集 |
| 库存三量 | `GET /inventory-service/inventory/list` | 演示数据集 |
| 基础资料四个分页 | 产品 / 物料 / BOM / 工艺路线查询接口 | 产品取演示数据集；物料、BOM、工艺路线明确提示“需连接网关” |
| 库存作业 | 安全线、预留、领料退料、对账全部走真实接口 | 整块明确提示演示模式不可用 |

早期版本里“生产趋势”折线是用线性插值伪造的计划 / 完成累计曲线，后端并没有时间序列接口，已整体移除；工单状态占比原先按当前页 `state.orders` 统计（live 只有一页 10 条），也改为使用服务端的全库统计。

### 6.2 写操作的边界

- **报工**：单号由网关 `GET /report/new-no` 签发并只读展示；申请失败留空，由服务端自动生成（`ReportCreateDTO.reportNo` 可空）。
- **派工**：候选人来自 `GET /system/user/list`，前端与后端都过滤 `status=1`，停用账号不能被派工。
- **领料 / 退料**：单号由服务端生成；批次管理物料不填批次号会被库存服务拒绝，这是批次追溯的强制约束，前端只做提示不做放行。
- **基础资料**：只读。产品 / 物料 / BOM / 工艺路线的写入接口本期未接入，页面不渲染新建、编辑、删除按钮。
- **对账**：`POST /inventory/reconcile` 返回差异条数；`autoFix=false` 只检查，`=true` 按流水账重算修复。

## 7. 已知范围

- 基础资料页（`#/basic`）是**只读**视图：产品、物料、BOM、工艺路线的维护表单与写入接口本期未接入。
- 网关未提供跨工单的质检单列表接口，也未有趋势环比、领料单全局列表、角色 / 菜单权限、消息通知铃铛等能力，前端不伪造这些入口。
- 离线演示中的部分状态变化是前端模拟；连接网关后以服务端状态机与 CAS 结果为准。
- 工作台采用 hash 路由，避免直接访问 `/orders` 时依赖额外的 SPA 回退配置。
- 工序按钮由 `TASK_TRANSITIONS` 镜像后端 `WorkTaskStatus.TRANSITIONS` 推导；后端迁移表变更时需同步该常量。
