# 生产工作台：设计说明与使用方式

## 1. 目标用户与核心任务

工作台主要服务三类现场角色：

| 角色 | 进入页面后最先要回答的问题 | 页面中的对应位置 |
|---|---|---|
| 生产计划员 / 车间主管 | 今天做到哪了？哪张单会拖交期？ | 总装随工单、工单队列、需要你决定 |
| 班组长 / 操作工 | 当前工序要做什么？怎么报工或暂停？ | 工艺路线、当前工序、工序详情抽屉 |
| 质检 / 仓库协同人员 | 哪道工序卡在质检？哪个物料有缺口？ | 质量放行、物料齐套、批次追溯 |

核心任务按照现场决策顺序排列，而不是按照数据库实体排列：

1. **看清当前节拍**：当前工单、当前工序、已报工数量、剩余交期。
2. **识别阻断点**：缺料暂停、待质检、已审核未下达。
3. **执行下一步**：开始、暂停、完工、报工、放行、下达。
4. **必要时追溯**：从成品批次回到物料批次与供应商。

## 2. 设计概念：数字随工单

制造业里，随工单会跟着一批产品穿过各道工序，记录数量、责任人和放行结果。本页面把这一现场物件转成数字界面：

- 首屏不是通用的“大数字 + 渐变卡片”，而是一张正在流动的随工单。
- 工艺路线用真实工序号（10 / 20 / 30）连接，质检点以菱形门禁标记。
- 当前工序是一个信号灯节点，路线只填充到当前节点；完成、进行中、待开始有不同结构状态。
- 右侧“需要你决定”只放会阻断后道的事件，不把所有通知平铺。

页面采用的独特视觉语言来自车间本身：矿物灰绿底板、涂装车间深绿、安全信号橙、工艺蓝图网格。深绿和海报式大标题承载“现场”，橙色只留给当前风险与主操作。

## 3. 字体、色彩与版式

### 字体

- 中文正文与标题：`HarmonyOS Sans SC / Source Han Sans SC / Microsoft YaHei`，优先保证中文的可读性和工业感。
- 数据与编号：`Bahnschrift SemiCondensed`，用于工单号、批次号、时间、数量和进度，形成“仪表读数”与中文正文的清晰分工。
- 数字启用 tabular numerals，便于队列内纵向比较。

### 色彩

| Token | 色值 | 用途 |
|---|---|---|
| `--board` | `#e6eae4` | 车间调度板底色 |
| `--paper` | `#f6f7f1` | 工单与数据纸面 |
| `--ink` | `#17241f` | 正文与决策栏 |
| `--forest` | `#1e4b41` | 当前工单、主操作、工艺路线 |
| `--signal` | `#d64b2b` | 风险、暂停、当前工位 |
| `--caution` | `#bd8a23` | 质检门禁与提醒 |

### 版式

- 左侧固定导航承载工厂层级；主区域以随工单为全宽视觉锚点。
- 指标轨使用连续刻线而不是四个同构圆角卡片。
- 下半区是 2:1 不对称布局：左侧工单队列，右侧决策栏。
- 设备宽度低于 820px 时切换为底部导航，随工单与操作按钮纵向重排。

### 动效

- 页面载入只做一次工艺路线填充，终点落在当前工序。
- 当前工位使用一个缓慢的雷达脉冲，表达“正在发生”而不是装饰。
- 抽屉、对话框和 Toast 由用户操作触发。
- 在 `prefers-reduced-motion: reduce` 下关闭这些动画。

## 4. 页面路由

工作台使用无需服务端回退的 hash 路由，现有 REST 路由保持不变：

| 页面路由 | 内容 | 调用的现有接口 |
|---|---|---|
| `#/today` | 今日生产、随工单、决策栏、批次脉络 | 工单分页、工单详情、库存列表 |
| `#/orders` | 工单列表、筛选、新建工单 | `GET /production-service/order/page`、`POST /production-service/order` |
| `#/orders/:id` | 工艺路线、数量、状态历史、工单流转 | `GET /production-service/order/{id}`、`POST /production-service/order/{id}/transit` |
| `#/tasks` | 工序任务队列与状态操作 | `POST /production-service/work-task/{id}/start|pause|resume|complete|pass-inspection|reject-inspection` |
| `#/materials` | 现有量 / 预留量 / 可用量 | `GET /inventory-service/inventory/list` |
| `#/trace` | 反向与正向批次路径 | `GET /quality-service/trace/backward` |
| `#/quality` | 待质检任务与放行、退回 | 工序任务放行 / 退回接口 |

## 5. 运行方式

### 由网关直接托管（推荐）

前端文件位于 `smart-gateway/src/main/resources/static/`，随网关 Jar 一起发布：

```bash
mvn -pl smart-gateway -am package -DskipTests
java -jar smart-gateway/target/smart-gateway-*.jar
```

打开 `http://localhost:9000/`。前端与 REST 接口同源，不需要额外配置 CORS。静态资源已加入网关鉴权白名单，登录接口仍使用原有 `/system/auth/login`。

### 仅预览界面

```bash
python -m http.server 4173 --directory smart-gateway/src/main/resources/static
```

打开 `http://127.0.0.1:4173/`。没有网关时会自动使用本地演示数据；点击右上角账号可输入 `planner / 123456` 尝试连接网关。

## 6. 真实接口与演示数据

- 默认进入**演示数据**模式，所有按钮可操作并在浏览器内存中回放状态变化，适合无数据库时浏览。
- 通过右上角“接口”或账号入口登录成功后进入**真实接口**模式，订单、工序、报工、库存和追溯操作会走现有网关路由。
- 登录失败不会静默伪装成功，会展示接口错误并保留演示数据。
- 前端不存储密码；JWT 存在 `localStorage`，401 时清除并回退到演示模式。

## 7. 已知范围

- 当前只覆盖生产执行核心工作台，不包含产品、BOM、工艺路线的完整维护表单。
- 离线演示中的部分状态变化是前端模拟；连接网关后以服务端状态机与 CAS 结果为准。
- 工作台采用 hash 路由，避免直接访问 `/orders` 时依赖额外的 SPA 回退配置。
