# 部署文档

> 覆盖三种部署方式：本机直接运行、Docker Compose、手工分步部署。
> 并附**故障排查手册**（本项目实际踩过的坑）。

---

## 1. 环境要求

| 依赖 | 最低版本 | 必需 | 用途 |
|---|---|---|---|
| JDK | 21 | ✅ | 运行（`JAVA_HOME` 需配置） |
| Maven | 3.8 | ✅ | 构建 |
| MySQL | 8.0 | ✅ | 5 个独立库 |
| Redis | 7 | ⭕ | 缓存/幂等（未启动不影响主流程） |
| RabbitMQ | 3.x | ⭕ | 异步消息（未启动时 outbox 落库 + 定时兜底） |
| Nacos | 2.x+ | ⭕ | 注册/配置（未启动时用直连地址） |
| Docker | 24+ | ⭕ | 容器化部署 |

**端口占用**：

| 端口 | 服务 | 说明 |
|---|---|---|
| 3306 | MySQL | |
| 6379 | Redis | 可选 |
| 5672 / 15672 | RabbitMQ AMQP / 管理台 | 可选 |
| 8848 / 9848 | Nacos 控制台 / gRPC | 可选 |
| **9000** | **gateway** | 统一入口 |
| 9001–9005 | 各业务服务 | 各服务 Knife4j 文档 |

## 2. 方式一：本机直接运行（开发调试推荐）

### 2.1 初始化数据库

```powershell
$mysql = "mysql"   # 或完整路径，如 "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe"
$files = @(
  "00_create_databases.sql",
  "01_schema_product.sql",
  "02_schema_production.sql",
  "03_schema_inventory.sql",
  "04_schema_quality.sql",
  "05_schema_system.sql",
  "06_init_data.sql"
)
foreach ($f in $files) {
  Get-Content "sql\$f" -Raw -Encoding UTF8 |
    & $mysql -uroot -p123456 --default-character-set=utf8mb4
}
```

> ⚠️ `00_create_databases.sql` 会 `DROP DATABASE`，**重复执行会清空数据**。

### 2.2 构建

```bash
mvn clean package -DskipTests
```

> 💡 **本机离线环境需带 `-s .mvn/settings.xml`**，原因见 `docs/环境与构建说明.md`。

### 2.3 启动（6 个终端或后台进程）

```bash
# 基础设施未启动时的启动参数（关闭相关依赖）
java -jar smart-product/target/smart-product-1.0.0.jar \
     --spring.cloud.nacos.discovery.enabled=false

java -jar smart-inventory/target/smart-inventory-1.0.0.jar \
     --spring.cloud.nacos.discovery.enabled=false \
     --smart.scheduling.enabled=false

java -jar smart-production/target/smart-production-1.0.0.jar \
     --spring.cloud.nacos.discovery.enabled=false \
     --smart.mq.enabled=false          # 未装 RabbitMQ 时

java -jar smart-quality/target/smart-quality-1.0.0.jar \
     --spring.cloud.nacos.discovery.enabled=false

java -jar smart-system/target/smart-system-1.0.0.jar \
     --spring.cloud.nacos.discovery.enabled=false

java -jar smart-gateway/target/smart-gateway-1.0.0.jar \
     --spring.cloud.nacos.discovery.enabled=false
```

### 2.4 验证

```bash
# 1. 检查端口
netstat -ano | findstr ":900"

# 2. 健康检查
curl http://localhost:9002/actuator/health

# 3. 完整业务链路（推荐）
java demo/FullChainDemo.java
```

预期输出结尾：

```
  通过检查点: 50
  失败检查点: 0

*** 完整业务闭环验证通过 ***
```

## 3. 方式二：Docker Compose 一键部署

> ⚠️ **诚实声明**：本项目的开发机 Docker Desktop 守护进程未运行，
> `docker compose up` **未做实际验证**。编排文件按 Spring Boot 官方最佳实践编写，
> 但首次运行可能需要调整（见下方"已知注意点"）。

### 3.1 启动

```bash
# 构建镜像并启动全部（首次较慢，需下载基础镜像 + Maven 依赖）
docker compose up -d --build

# 查看启动状态
docker compose ps

# 查看某服务日志
docker compose logs -f smart-production
```

### 3.2 验证

| 地址 | 用途 |
|---|---|
| http://localhost:8848/nacos | Nacos 控制台（nacos/nacos） |
| http://localhost:15672 | RabbitMQ 管理台（guest/guest） |
| http://localhost:9000/system/auth/login | 网关入口 |
| http://localhost:9002/doc.html | 产品服务文档 |

### 3.3 启动顺序

```
mysql/redis/rabbitmq/nacos（healthcheck 通过）
  → mysql 自动执行 sql/ 初始化脚本
  → smart-system / product / inventory / quality
  → smart-production（依赖 product + rabbitmq）
  → smart-gateway（最后启动，依赖全部业务服务）
```

### 3.4 常用命令

```bash
docker compose down          # 停止（保留数据卷）
docker compose down -v       # 停止并删除数据（重跑初始化脚本用）
docker compose restart smart-production
docker compose scale smart-production=2   # 多实例（注意定时任务需加锁）
```

### 3.5 已知注意点

| 注意点 | 说明 |
|---|---|
| **MySQL 初始化脚本只执行一次** | 数据卷已存在时不会重跑。改表结构需 `down -v` |
| **镜像构建需要联网** | `mvn dependency:go-offline` 需访问 Maven 仓库 |
| **构建上下文是根目录** | Dockerfile 里 COPY 了父 pom 和 smart-common |
| **Nacos 鉴权已关闭** | 演示环境。生产必须开 `NACOS_AUTH_ENABLE=true` 并配置 token |
| **JWT 密钥** | 生产必须通过 `JWT_SECRET` 环境变量覆盖 |
| **资源占用** | 全套约需 4GB 内存（MySQL 1G + Nacos 512M + 6 个 JVM） |

### 3.6 生产环境必须修改的配置

| 配置项 | 演示值 | 生产要求 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | 123456 | 强密码 |
| `JWT_SECRET` | 代码内默认值 | 环境变量注入，定期轮换 |
| `NACOS_AUTH_ENABLE` | false | true + 配置 token |
| `GATEWAY_AUTH_ENABLED` | true | 保持 true |
| 业务服务端口 | 对外暴露 | **只监听内网**（防伪造 X-User-Id 头） |
| 日志级别 | DEBUG | INFO/WARN |
| RabbitMQ 账号 | guest/guest | 独立账号 + 权限控制 |

## 4. 方式三：手工分步部署（生产参考）

### 4.1 基础设施

```bash
# MySQL
docker run -d --name mes-mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD='<强密码>' \
  -v mes-mysql-data:/var/lib/mysql \
  -v $(pwd)/sql:/docker-entrypoint-initdb.d:ro \
  mysql:8.0 --character-set-server=utf8mb4 --collation-server=utf8mb4_general_ci

# Redis（可选）
docker run -d --name mes-redis -p 6379:6379 redis:7-alpine

# RabbitMQ（可选）
docker run -d --name mes-rabbitmq -p 5672:5672 -p 15672:15672 \
  -e RABBITMQ_DEFAULT_USER=mes -e RABBITMQ_DEFAULT_PASS='<强密码>' \
  rabbitmq:3-management-alpine

# Nacos（可选）
docker run -d --name mes-nacos -p 8848:8848 -p 9848:9848 \
  -e MODE=standalone -e NACOS_AUTH_ENABLE=true \
  nacos/nacos-server:v2.3.2
```

### 4.2 服务启动顺序与依赖

```
1. MySQL 就绪（healthcheck）
2. Nacos 就绪
3. smart-system   （只依赖 MySQL + Nacos）
4. smart-product  （只依赖 MySQL + Nacos）
5. smart-inventory（只依赖 MySQL + Nacos）
6. smart-quality  （只依赖 MySQL + Nacos）
7. smart-production（依赖 MySQL + Nacos + product + RabbitMQ）
8. smart-gateway  （依赖 Nacos + 全部业务服务）
```

**为什么 gateway 最后启动**：它要转发到所有后端，先启动会返回 503。

### 4.3 systemd 服务示例

```ini
# /etc/systemd/system/mes-product.service
[Unit]
Description=Smart Manufacturing - product service
After=network.target mysql.service

[Service]
Type=simple
User=mes
WorkingDirectory=/opt/mes
Environment="JAVA_OPTS=-Xms512m -Xmx1g -Dfile.encoding=UTF-8"
Environment="MYSQL_HOST=127.0.0.1"
Environment="MYSQL_PASSWORD=<强密码>"
Environment="NACOS_ADDR=127.0.0.1:8848"
ExecStart=/usr/bin/java $JAVA_OPTS -jar /opt/mes/smart-product-1.0.0.jar
Restart=always
RestartSec=10
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
```

## 5. 配置项说明

所有配置支持环境变量覆盖（`${VAR:default}` 语法）。

### 5.1 通用

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `MYSQL_HOST` | localhost | MySQL 地址 |
| `MYSQL_PORT` | 3306 | |
| `MYSQL_USER` | root | |
| `MYSQL_PASSWORD` | 123456 | ⚠️ 生产必改 |
| `NACOS_ADDR` | 127.0.0.1:8848 | Nacos 地址 |
| `NACOS_REGISTER` | true | 是否注册到 Nacos |
| `JAVA_OPTS` | — | JVM 参数 |

### 5.2 各服务特有

| 服务 | 环境变量 | 默认值 | 说明 |
|---|---|---|---|
| system | `JWT_SECRET` | 内置默认 | ⚠️ 生产必改 |
| system | `JWT_EXPIRE_MINUTES` | 480 | token 有效期（8h 一个班次） |
| system | `REDIS_HOST` / `REDIS_PORT` | localhost / 6379 | |
| production | `RABBITMQ_HOST` / `RABBITMQ_PORT` | localhost / 5672 | |
| production | `RABBITMQ_USER` / `RABBITMQ_PASSWORD` | guest / guest | |
| production | `SMART_MQ_ENABLED` | true | **false 时 outbox 仍落库，业务不受影响** |
| production | `PRODUCT_SERVICE_URL` | http://127.0.0.1:9002 | 基础资料服务地址 |
| production | `SMART_SCHEDULING_ENABLED` | true | 定时任务开关 |
| gateway | `JWT_SECRET` | 内置默认 | **必须与 system 一致** |
| gateway | `GATEWAY_AUTH_ENABLED` | true | false 时关闭鉴权（仅本地调试） |
| gateway | `SYSTEM_SERVICE_URL` 等 | 各 localhost 端口 | 路由目标 |
| inventory | `SMART_SCHEDULING_ENABLED` | true | 对账/预留清理定时任务 |

**关键点：`JWT_SECRET` 必须在 system 和 gateway 两个服务里完全一致**，
否则网关验签失败 → 所有请求 401。

## 6. 故障排查手册

> 以下都是本项目**实际踩过**的坑。

### 6.1 启动类问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `Port 9002 was already in use` | 旧进程未退出 | `netstat -ano \| findstr :9002` 找 PID → `taskkill /PID xxx /F` |
| `Could not register rabbit listener endpoint ... no 'RabbitListenerContainerFactory' with id 'manualAckContainerFactory'` | `smart.mq.enabled=false` 时 RabbitConfig 不加载，但监听器仍注册 | 已修复：监听器加 `@ConditionalOnProperty(name="smart.mq.enabled")` |
| `NoSuchMethodError` / `ClassNotFoundException`（Nacos 相关） | Spring Boot / Spring Cloud / SCA 版本不匹配 | 严格用 Boot 3.3.6 + Cloud 2023.0.1 + SCA 2023.0.1.0 |
| 网关启动报 `Spring MVC found on classpath` | gateway 模块引入了 `spring-boot-starter-web` | gateway **不能**引 web（它基于 WebFlux） |
| 应用启动后进程立刻退出 | 在交互式 shell 里启动，父进程退出被杀 | 用后台作业/`nohup`/systemd 托管 |

### 6.2 数据库问题

| 现象 | 原因 | 解决 |
|---|---|---|
| `Access denied for user 'root'@'localhost'` | 密码错 | 检查 `MYSQL_PASSWORD` |
| `Public Key Retrieval is not allowed` | MySQL 8 默认 `caching_sha2_password` | JDBC URL 加 `allowPublicKeyRetrieval=true` |
| 中文乱码 | 连接字符集不对 | URL 加 `characterEncoding=utf8`；脚本执行用 `--default-character-set=utf8mb4` |
| `Table 'smart_product.product' doesn't exist` | 没执行建表脚本 | 按 00→06 顺序执行 |
| 初始化数据重复插入失败 | 未先执行 `00_create_databases.sql`（它含 DROP） | 重跑 `00_create_databases.sql` 再跑 06 |
| `Data truncation: Incorrect datetime value` | 时区/格式不符 | URL 加 `serverTimezone=Asia/Shanghai`；JSON 时间用 ISO 格式 `2025-01-20T18:00:00` |

### 6.3 鉴权问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 所有请求 401 | gateway 的 `JWT_SECRET` 与 system 不一致 | 两个服务配同一个 `JWT_SECRET` |
| 登录返回 401「用户名或密码错误」 | 密码不对，或初始化数据的 BCrypt 哈希与密码不匹配 | 用 `POST /auth/hash` 生成新哈希；初始化数据对应密码是 `123456` |
| token 带上了但仍 401 | header 格式不对 | 必须是 `Authorization: Bearer <token>`（注意空格） |
| 想本地调试关掉鉴权 | — | `GATEWAY_AUTH_ENABLED=false` |

### 6.4 跨服务调用问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 创建工单报 `40912 基础资料服务不可用` | smart-product 未启动或地址不对 | 确认 9002 已启动；检查 `PRODUCT_SERVICE_URL` |
| 报「产品未配置生效 BOM」但数据库里有 BOM | BOM 状态不是 `2-生效` | 调 `POST /bom/{id}/activate` 让它生效 |
| 网关返回 503 | 目标业务服务未启动 | 检查对应端口 |

### 6.5 业务逻辑问题（容易误判为 bug）

| 现象 | 其实是 | 说明 |
|---|---|---|
| 预留返回「可用库存不足」但明明有库存 | 可用量 = 现有量 − 预留量 | 可能其他工单已预留了。查 `reserved_quantity` |
| 对账报 `QUANTITY_DIFF` | 初始化库存没写流水 | 必须同时插入"期初入库"流水（`06_init_data.sql` 已处理） |
| 重复预留直接返回成功 | 幂等设计 | `uk_order_material` 保证同一工单同一物料只预留一次 |
| 报工报「只有进行中的工序可以报工」 | 状态门禁 | 先 `POST /work-task/{id}/start` |
| 工序无法开始，提示前道未完成 | 工艺纪律 | 先完成前道；若前道是质检点需先质检放行 |
| 超报校验返回 40905 但数量看起来没超 | 看的是"本次"，要看"累计+本次" | 提示信息里有"计划/已报/本次"三个数 |
| `maxDepth=1` 追溯只有 1 层 | 深度限制生效 | 响应里 `truncated=true` 表示结果不完整 |

### 6.6 构建问题（本机特殊环境）

| 现象 | 原因 | 解决 |
|---|---|---|
| `Cannot access central in offline mode` | 无网络且缓存缺构件 | 用 `.mvn/settings.xml`（配了代理） |
| `AccessDeniedException: ..._remote.repositories` | `~/.m2` 只读 | settings 里把 `localRepository` 指向工作区 `.mvn/repo` |
| Lombok `@Data` 不生效，报「找不到符号 getCode()」 | ①pom 缺处理器配置 ②**同一模块有其它真实编译错误导致注解处理轮次中止** | 已修复：显式配 `annotationProcessors` + Lombok 升到 1.18.46。**若再出现，先找该模块的第一个真实语法错误** |
| Mockito `Could not self-attach to current VM` | 受限环境无法派生进程 | 已改用 JDK 动态代理手写桩（`support/Stub.java`） |

> 详细环境说明见 [`docs/环境与构建说明.md`](./环境与构建说明.md)

## 7. 监控与运维

### 7.1 健康检查

每个服务都暴露 Spring Boot Actuator：

```bash
curl http://localhost:9002/actuator/health
```

**注意**：返回 `DOWN` 不一定代表服务不可用。
例如 Redis/RabbitMQ 未启动时，健康检查会显示对应组件 `DOWN`，
但数据库 `db` 是 `UP`，业务接口正常。

```json
{
  "status": "DOWN",
  "components": {
    "db": { "status": "UP" },
    "redis": { "status": "DOWN", "details": {"error": "Unable to connect to Redis"} },
    "rabbit": { "status": "DOWN" }
  }
}
```

**生产环境应把可选组件从健康检查中排除**，否则 K8s 会误判服务不健康而重启。

### 7.2 业务监控点

| 监控项 | 查询方式 |
|---|---|
| outbox 待投递/失败数 | `GET /mq/outbox/stats` |
| 工单各状态数量（看板） | `GET /order/stats/status` |
| 低库存预警 | `GET /inventory/below-safety` |
| 库存对账异常 | `POST /inventory/reconcile` → 查 `inventory_reconcile_log` |
| 不良代码统计 | `GET /inspection/defect-stats` |
| 状态流转历史 | `GET /order/{id}` 的 `statusLogs` |

### 7.3 关键日志

日志格式已带 `traceId`：

```
2026-10-31 14:26:48.536 [http-nio-9003-exec-1] INFO  [a1b2c3d4e5f6] c.s.p.s.ProductionOrderService - [工单流转] orderNo=WO... 草稿 → 已审核
```

凭 `traceId` 可把一条链路在多个服务的日志串起来（网关生成并透传）。

### 7.4 定时任务

| 任务 | 时间 | 作用 | 开关 |
|---|---|---|---|
| outbox 投递 | 每 3 秒 | 补发待投递消息 | `SMART_MQ_ENABLED` |
| outbox 失败告警 | 每 5 分钟 | 记录失败数量 | 同上 |
| 预留过期清理 | 每天 02:00 | 释放过期预留 | `SMART_SCHEDULING_ENABLED` |
| 库存对账 | 每天 03:00 | 检测账实差异 | 同上 |

## 8. 备份与恢复

```bash
# 备份
mysqldump -uroot -p --databases smart_system smart_product smart_production \
  smart_inventory smart_quality > mes-backup-$(date +%Y%m%d).sql

# 恢复
mysql -uroot -p < mes-backup-20251031.sql
```

**建议**：生产环境配置每日全量备份 + binlog 增量，保留 30 天。

## 9. 已知部署限制

1. **Docker Compose 未实跑验证**（开发机 Docker 守护进程未运行）。
2. **未配置 Nginx 反向代理 / HTTPS**：生产应在网关前加 Nginx 做 TLS 终止与限流。
3. **未配置日志采集**（ELK/Loki）：日志只输出到 stdout。
4. **未配置 APM 链路追踪**（SkyWalking/Zipkin）：只做了 traceId 透传。
5. **未做蓝绿/灰度发布**。
6. **业务服务端口直接暴露**：生产必须只开网关端口，业务服务仅内网可达。
